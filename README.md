# 채점노트 — 엔트리 숫자맞추기 수행평가

학생 `.ent` 파일을 브라우저에서 분석하는 한국어 웹앱입니다. **AI API·계정·서버·구글 시트 없이 규칙 기반으로 채점**합니다. 학생 파일은 외부 서버로 전송하지 않습니다.

## 선생님이 바로 사용하기

완성본은 `dist/index.html`입니다. 파일을 내려받아 Chrome 또는 Edge에서 열면 됩니다. 인터넷 연결이나 별도 프로그램 설치가 필요하지 않습니다. 파일 이름을 `채점노트.html`로 바꿔도 됩니다. 브라우저 보안 정책에 따라 로컬 파일 실행이 제한되는 PC에서는 아래 웹서버 방식 또는 학교가 허용한 HTTPS 정적 호스팅을 사용하세요.

1. **예시로 체험하기**를 눌러 만점·검토 필요 작품을 먼저 살펴보세요. 체험 데이터는 성적표에 저장하지 않습니다.
2. 기본 모드는 **채점만**입니다. 결과를 보관하려면 **채점 후 성적표에 기록**으로 바꾸고 학생 파일을 선택하세요. 또는 채점 상세에서 **성적표에 기록**을 누르세요.
3. 파일명은 `20712홍길동.ent`, `20712_홍길동.ent`, `PC-12_20712_홍길동.ent`처럼 학번과 이름을 넣습니다. 예시 학번은 2학년 7반 12번입니다. 프로젝트 이름은 학생 이름으로 사용하지 않습니다.
4. 학번 없는 파일도 채점합니다. 결과의 **학번 입력**에서 보완하세요. 현재 성적표의 학년이나 번호 범위를 벗어나면 기록하지 않고 안내합니다.
5. 결과 행을 누르면 13개 기준과 모든 오브젝트의 의사코드를 볼 수 있습니다. **검토 필요** 항목은 우선 감점하지 않으므로 점수는 잠정 값입니다. 교사가 인정·감점을 결정하세요. 각 항목의 자동 판정으로 돌아갈 수도 있습니다.
6. **반별 성적표**에서 명단과 점수를 편집하세요. 명단 붙여넣기는 엑셀의 `번호`, `이름` 두 열을 지원합니다. 기존 명단 이름은 재채점 시 유지합니다. 같은 학번의 새 파일을 기록하면 기존 결과를 갱신합니다.
7. **성적표 내려받기**에서 현재 반/전체 반, 엑셀/CSV를 선택하세요. 엑셀은 반별 시트를 생성합니다.
8. 작업이 끝나면 **백업 내보내기**로 JSON을 보관하세요. 다른 PC나 사이트에서는 **백업 불러오기**로 복원합니다. 가져오기 전 덮어쓰기 확인창이 표시됩니다.

### 저장을 꼭 확인하세요

- 성적표·명단·교사 판정·의사코드는 현재 브라우저의 `localStorage`에 저장합니다. 원본 `.ent`나 이미지·음원은 저장하지 않습니다.
- **사이트 데이터 삭제, 비공개 모드 종료 시 기록이 사라질 수 있습니다.** 브라우저·PC·웹사이트 주소가 바뀌면 같은 기록이 보이지 않습니다.
- 로컬 HTML의 저장 영역은 브라우저 정책에 따라 다릅니다. 직접 여는 방식도 Chromium에서 저장·새로고침·백업 복원을 검증했지만, 안정적인 운영은 고정된 HTTPS 주소를 권장합니다. HTML 파일을 옮기거나 이름을 바꾸기 전에도 JSON 백업을 만드세요.
- 저장 공간이 부족하거나 저장이 차단되면 오류를 표시합니다. 이때는 **즉시 JSON 백업**을 내려받으세요. 백업 안내 해제는 다운로드 요청을 기준으로 하므로 실제 파일 저장도 확인하세요.
- 엑셀·CSV는 공유용입니다. 항목별 판정까지 복원하려면 **JSON 백업**이 필요합니다. 이름과 성적이 포함되므로 학교의 자료 보관 기준을 따르세요.
- **채점만** 결과는 새로고침 시 사라집니다. 저장하지 않은 결과가 있으면 페이지를 나갈 때 브라우저 확인을 요청합니다.
- 성적표는 한 학년의 1~9반용입니다. 기본값은 2학년·반별 33명입니다. 다른 학년·학기로 바꿀 때는 백업 후 사용 안내에서 **새 성적표 시작하기**를 선택하세요.
- 설정의 기본점수 변경은 새로 채점하는 작품에 적용합니다. 기존 성적표 점수는 바꾸지 않습니다. 수행점수는 0~15, 기본점수는 0~100입니다.

## 채점 범위와 한계

정답 난수는 하한 1, 상한 10으로 설정해야 합니다. 1~100, 0~10 등 다른 범위는 ③ 항목에서 1점 감점하며 별도 중복 감점은 하지 않습니다. 변수·계산식으로 범위를 지정해 자동 확인할 수 없는 경우 교사 검토로 남깁니다. 기존에 저장된 점수는 자동 변경되지 않으므로 학생 파일을 다시 선택해 재채점하세요. 앱 교체나 웹주소 이동 전에는 JSON 백업을 내려받고 새 페이지에서 불러오세요.

수행 15점 + 기본 10점(설정 가능)입니다. 변수 `정답`, `정답횟수`의 공백 차이는 허용합니다. ID가 없는 변수 참조를 이름으로 복구하지 않습니다. 유일한 구조적 별칭을 확인할 수 있으면 변수명 문제는 한 번만 1점 감점해 같은 문제를 항목별로 중복 차감하지 않습니다.

실제 엔트리 형식(gzip → tar → `temp/project.json` → 문자열 `script` 재파싱)을 분석합니다. 시작 스레드·반복문의 구조와 입력이 작음/같음/큼인 경로를 살펴보고 피연산자 순서, 안내 방향, 마지막 정답 입력의 횟수, 종료 후 횟수 안내를 확인합니다. 다른 오브젝트의 정답 숨기기도 검사합니다.

이는 **임의의 엔트리 프로그램 전체를 실행하는 에뮬레이터가 아닙니다.** 표준 숫자맞추기 구조를 위한 정적 분석기입니다. 문구 의미는 규칙과 패턴으로 판정하며 자연어 전체를 이해하지 못합니다. 모호한 시작 안내·방향 문구, 지원 범위 밖의 블록·조건식, 여러 게임 스레드나 복잡한 중첩은 교사 검토로 남깁니다. 최종 성적 확정 전 항목과 의사코드를 확인하세요.

파일당 25MB, 해제 후 80MB, 프로젝트 JSON 8MB, 의사코드 30만 자, 한 번에 100개까지 처리합니다. gzip/tar 손상·헤더 체크섬·입력 구조·백업 형식을 확인합니다. 학생 코드를 `eval`하거나 실행하지 않습니다. 분석은 별도 Web Worker에서 수행합니다.

## 개발 실행

Node.js 22 이상과 npm을 권장합니다. 이 클라우드에서는 Node.js 24로 검증했습니다.

```sh
npm ci
npm run dev
```

브라우저에서 개발 서버가 안내하는 주소를 열면 됩니다. 읽기 전용 홈 디렉터리를 사용하는 이 클라우드에서는 설치에 다음 명령을 사용합니다.

```sh
npm ci --cache /workspace/.npm-cache --no-audit --no-fund
```

### 빌드와 배포

```sh
npm run build
```

`dist/index.html` 한 파일에 CSS·JavaScript·아이콘·압축 파서·엑셀 내보내기·분석 Worker가 모두 들어갑니다. 외부 CDN이나 폰트를 불러오지 않습니다. 파일을 직접 열거나 GitHub Pages 등의 HTTPS 정적 호스팅에 올릴 수 있습니다. GitHub Pages는 빌드 결과 `dist`를 배포 대상으로 지정하세요. 이 저장소의 downloads/entry-grading-notebook.zip에서 완성본을 받을 수 있습니다. GitHub Pages 게시용 파일은 gh-pages 브랜치에 둡니다. 아래의 최초 게시 설정이 필요합니다.

로컬 웹서버에서 빌드 결과 확인:

```sh
npm run preview
```

### 브라우저에서 바로 열기 (GitHub Pages)

앱 사용 주소는 `https://classical96-work.github.io/vibe-coding-work/`입니다. 게시가 활성화되지 않았다면 저장소 관리자가 GitHub **Settings → Pages → Source: Deploy from a branch → Branch: gh-pages → /(root) → Save**로 게시를 활성화할 수 있습니다. 설정 화면: https://github.com/classical96-work/vibe-coding-work/settings/pages

이후 새 버전을 게시하려면 저장소에서 다음 명령을 명시적으로 실행합니다. 빌드 결과의 `index.html`과 `.nojekyll`만 게시하며, 현재 작업 브랜치·소스 파일을 유지합니다. 기존 배포 커밋을 이어받고 강제 푸시는 사용하지 않습니다.

```sh
npm run publish:pages
```

GitHub 저장소 쓰기 권한이 필요합니다. 사이트 게시 여부와 HTTPS 응답 확인은 별도로 해야 합니다. 학생 파일·명단·성적은 게시하지 않습니다. PC의 로컬 HTML에서 사용하던 기록은 먼저 JSON 백업을 내려받아 웹주소에서 불러오세요. 주소가 바뀌면 브라우저 저장 영역도 달라집니다.

앱 사용에는 외부 계정·API 키·Apps Script 설정이 필요 없습니다.

### 검증

```sh
npm test
npm run build
```

합성 엔트리 픽스처로 필수 감점 사례, 피연산자 반전, 마지막 입력 횟수, 모호한 문구, 실제 gzip/tar 파싱, 손상 파일·백업 거부 등을 검사합니다. 사용자 원본 샘플은 학생 메타데이터 보호를 위해 저장소에 포함하지 않았습니다. 실제 `.ent` 검증은 경로를 지정하면 실행하며, 지정하지 않으면 해당 테스트 하나는 건너뜁니다.

```sh
SAMPLE_ENT=/path/to/sample.ent npm test
```

브라우저 기능 검증(Chromium 설치가 필요하며 별도 터미널에서 개발 서버 실행):

```sh
npx playwright install chromium
npm run dev
# 다른 터미널
SAMPLE_ENT=/path/to/sample.ent npm run test:ui
# 빌드 HTML을 직접 여는 방식도 검증 가능
APP_URL=file:///absolute/path/to/dist/index.html SAMPLE_ENT=/path/to/sample.ent npm run test:ui
```

브라우저 검증은 예시 채점·교사 판정, 실제 파일 업로드·학번 보완·명단, 새로고침 저장, 재채점, 수동 점수 계산, JSON 복원, 실제 엑셀/CSV 내용, 모바일 화면, JavaScript 오류를 검사합니다. 실제 파일 단계는 `SAMPLE_ENT`를 지정했을 때 실행합니다. 결과 스크린샷은 `artifacts/`에 생성합니다.

특수 클라우드에서 이미 설치된 Chromium을 사용하는 경우 브라우저 도우미 모듈을 `CHROMIUM_HELPER`에 지정할 수 있습니다. 일반 사용자는 필요하지 않습니다.

## 코드 구성

- `src/parser.ts`: 압축·tar·엔트리 구조 검증, 학번 식별, 의사코드
- `src/grader.ts`: UI와 독립적인 순수 채점 함수와 점수 재계산
- `src/analysis.worker.ts`: 백그라운드 파일 분석
- `src/store.ts`: `ScoreStore` 인터페이스, 브라우저 저장소, 백업 검증
- `src/export.ts`: JSON 파일 다운로드, CSV·엑셀 출력
- `src/main.ts`, `src/style.css`: 한국어 UI, 반별 성적표, 검토·백업 흐름
- `tests/`: 요구 사례·손상 파일·실제 파일 선택 검증

엑셀은 ExcelJS를 사용합니다. ExcelJS의 Node 의존성 `uuid`는 사용 중인 v4 API 호환성을 유지하는 11.1.1 이상으로 고정해 알려진 이전 버전 취약점을 피합니다. 의존성 변경 시 잠금 파일과 엑셀 내보내기 검증을 함께 갱신하세요.
